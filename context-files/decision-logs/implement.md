# implement — decision log

2026-09-25  feature/w1-quiz-reliability  — Present quiz questions deterministically from the catalog (title + difficulty + link) and persist the session once with its presentation turn; removed the `wrap` prompt mode — rejected keeping the model "wrap" call with rollback-on-failure — a model call to restate a title is the root cause of orphaned active sessions and adds latency/cost for no value (A1 already mandates the raw problem).
2026-09-25  feature/w1-quiz-reliability  — Heal legacy orphans by appending the missing presentation turn in memory (persisted only with the next write) and send the `on_track` probe as an additive `question.probe` — rejected a storage migration / new `QuizSession` field — storage interfaces are frozen for this task and the nudge count is derivable from the transcript.
2026-09-25  feature/w1-quiz-reliability  — Heal a legacy orphan only when user turns == answered (a nudge spent while orphaned keeps counting via the A3 invariant) — rejected always appending a presentation turn — it would reset the nudge count and grant a second nudge.
2026-09-25  feature/w1-quiz-reliability  — Normalize catalog difficulty to Easy/Medium/Hard at the SPA boundary (`normalizeDifficulty` in lib/api.ts, used by fetchCatalog and the quiz card; bundled to avoid a conflict cycle with #54) — rejected changing the server wire casing — the curriculum's lowercase values are the public contract; one client-side normalizer is the single source of truth.
2026-09-25  feature/w1-quiz-reliability  — Supersedes the earlier "user turns == answered" heal rule: heal an orphan (and compute the no-boundary nudge fallback) from the transcript TAIL — empty, or ending in the terminal pair stamped with the latest answer's `at` → heal / 0 nudges; otherwise the tail is a probe — rejected whole-session turn counts — they include earlier questions' nudges, so the common orphan (Q1 nudged → answered → Q2 unpresented) was not healed and lost its Q2 nudge.
2026-09-25  feature/w2-localhost-hardening  — Enforce Host allowlist + same-origin + JSON-only checks inside `createCoachHandler` (pure helpers in `security.ts`), port pinned via a new optional `CoachHandlerDeps.port` — rejected doing it only in `server.ts` — the handler is what tests exercise, so the checks are covered without a socket and cannot be bypassed by another composition root.
2026-09-25  feature/w2-localhost-hardening  — Require `Content-Type: application/json` on ALL mutating `/api` requests, including body-less ones (`/api/quiz/end`, DELETE) — rejected "only when a body is present" — a no-cors fetch with no body sends no Content-Type and would slip past as a simple request; the SPA already sends JSON on every write.
2026-09-25  feature/w2-localhost-hardening  — Allow writes with neither `Origin` nor `Sec-Fetch-Site` — rejected requiring one — browsers always send one cross-site, so absence means a non-browser client (curl) that already runs as the user; keeps the documented curl examples working.
2026-09-25  feature/w2-localhost-hardening  — Treat `Origin: null` as "defer to Sec-Fetch-Site, reject if absent" — rejected plain reject — with `Referrer-Policy: no-referrer` browsers serialize our own /setup form post's Origin as `null`, so a strict reject would break /setup in real browsers.
2026-09-25  feature/w2-localhost-hardening  — /setup CSRF token is per-process (per handler) and embedded in the GET form, compared with `timingSafeEqual` — rejected a double-submit cookie — the form is only readable same-origin (Host allowlist + SOP), so a server-held token is simpler; restarting the server invalidates open forms.
2026-09-25  feature/w2-localhost-hardening  — Two CSPs: strict `default-src 'self'` (no inline script/style) for the SPA/API, script-free `style-src 'unsafe-inline'` for the server-rendered pages — rejected one shared CSP with `'unsafe-inline'` styles — the Vite build emits no inline script/style (verified dist-ui/index.html; React style props use CSSOM), so the SPA can stay strict.
2026-09-25  feature/w2-localhost-hardening  — /setup: validation failures and mkdir failures now return 400 (was 200) and only newly created dirs are chmod 0700 — rejected chmod-ing an existing dir — its permissions belong to the user.
2026-09-25  feature/w2-localhost-hardening  — Serve server-rendered pages (/setup, 404) with `Referrer-Policy: same-origin`, keep `no-referrer` for the SPA/API (review follow-up) — rejected same-origin globally — only the server pages submit forms; under no-referrer their form post's Origin is `null`, which Safari <16.4 / Firefox <90 (no Sec-Fetch-Site) could not prove same-origin; same-origin still sends nothing cross-origin, and the SPA's cors-mode fetches get a real Origin regardless.
2026-09-25  feature/w2d-server-data-dir  — Keep the active data dir as mutable state inside `createCoachHandler` (seeded from the boot-resolved `dataDir`/`dataDirSource`, or resolved once at creation from env/argv/`homeDir`) and pass it to the API as `ApiDeps.dataDir`; `handleApiRoute` loses its cookie parameter — rejected a process-global singleton — per-handler state keeps tests isolated and lets a "restart" be modelled as a new handler over the same injected home.
2026-09-25  feature/w2d-server-data-dir  — /setup on a pinned (flag/env) dir accepts the SAME path (creates it, no config.json write) and 400s any other path — rejected refusing every POST — the pinned dir may be missing at boot and /setup was already the documented way to create it.
2026-09-25  feature/w2d-server-data-dir  — Persist config.json BEFORE switching the in-process dir; a write failure returns 400 and keeps the old dir — rejected switch-then-persist — the server would silently use a dir it forgets on restart.
2026-09-25  feature/w2d-server-data-dir  — A dir from config.json is not auto-created at boot (only the default is) — rejected re-creating it — a dir the user removed must not silently reappear; the banner points to /setup.
2026-09-25  feature/w2d-server-data-dir  — Expire the legacy cookie on EVERY response whose request carries it (in the handler wrapper) and detect it by name only (value never decoded) — rejected expiring only on /api — any page load should clean it up; `parseCookies` was also made non-throwing on malformed escapes.
2026-09-25  feature/w2d-server-data-dir  — Body cap enforced twice: the transport stops buffering past 1 MiB (declared Content-Length or bytes received) but drains to the end, then the handler answers 413 (`bodyTooLarge`), and the handler also re-checks `body` length — rejected destroying the socket on overflow — the client got ECONNRESET instead of the 413; draining discards bytes without buffering.
