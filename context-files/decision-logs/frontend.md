# Decision log — frontend

Format: `YYYY-MM-DD  <branch/PR>  — decision — rejected alternative — why`

2026-09-25  feature/w3-catalog-filter  — Catalog search is instant (useMemo over `filterCatalog`) — rejected debouncing — ~175 problems filter in well under a frame; a debounce only adds lag and timer complexity to tests.
2026-09-25  feature/w3-catalog-filter  — Filter state lives in the URL query (`q`, `difficulty`, `status`) via `history.replaceState`, with small `currentSearch`/`replaceSearch` helpers added to the in-repo router — rejected component-only state and `pushState` per keystroke — reload/back-from-notes must keep the filter, and pushing per keystroke would flood the back stack; the router matches pathname only, so the query doesn't disturb routing.
2026-09-25  feature/w3-catalog-filter  — Filtering is pure and client-side over the existing `GET /api/catalog` data (lib/home.ts) — rejected a server-side filter endpoint — no API change needed, and it keeps product logic out of the component and unit-testable.
2026-09-25  feature/w3-catalog-filter  — [superseded below] Matching topics auto-expand by remounting each accordion (key includes filter active/inactive) with `defaultOpen` — rejected a fully controlled `open` prop — keeps CategoryAccordion's API small and lets a user's manual collapse stick while they keep typing; clearing collapses back to the default.
2026-09-25  feature/w3-catalog-filter  — Status chips reuse the existing `STATUS_LABELS` ("Not started", "Didn't understand") — rejected new "None"/"Did not understand" labels — one vocabulary with the per-row Status control.
2026-09-25  feature/w3-catalog-filter  — "N of M" counts distinct problem ids (M = API `totals.total`) — rejected summing per-topic matches — a problem listed under two topics would be double-counted.
2026-09-25  feature/w3-catalog-filter  — [superseded below] With a status filter on, changing a row's status re-filters immediately — rejected freezing the visible set — simplest model.
2026-09-25  feature/w3-catalog-filter (review #54)  — URL is the single source of truth: Home re-derives the filter on `popstate` (which `navigate()` also dispatches), only while the path is still Home — rejected a new location hook in the router — one listener covers nav-to-`/`, Back/Forward and in-app nav; the path guard stops a jump to /notes from wiping the remembered query.
2026-09-25  feature/w3-catalog-filter (review #54)  — Notes "Back to problems" goes to `lastHomeHref()` (Home's last query, in-memory in router.ts) — rejected `history.back()` when the previous entry was Home — the History API can't read the previous entry reliably; an in-memory query is simple and degrades to `/` on a direct notes load.
2026-09-25  feature/w3-catalog-filter (review #54)  — A row whose status changes under an active filter is pinned visible until the filter next changes (pinned rows count in "N of M") — rejected moving focus elsewhere — keeps the row and its focused control in place, so there is no surprise and no focus loss.
2026-09-25  feature/w3-catalog-filter (review #54)  — Home owns topic expansion: the user's own open set (unfiltered) plus a "collapsed while filtering" set that resets when the filter goes inactive — rejected the remount-key trick — Clear now restores the pre-filter open topics, and a topic collapsed mid-filter stays collapsed while typing.
2026-09-25  feature/w3-catalog-filter (review #54)  — URL facets parse case-insensitively and list commas are written unescaped (`difficulty=Easy,Hard`) — rejected strict case — hand-edited URLs should just work; parsing accepts both `,` and `%2C`.
2026-09-25  feature/data-page  — One `DataDirControl` (data-dir-control.ts) owns the active dir; `/setup` and `POST /api/data-dir` (incl. the legacy "Use it") both go through `choose()` — rejected duplicating the #60 /setup logic in api.ts — one validate/create/persist/switch path.
2026-09-25  feature/data-page  — Followed ADR 0009 D1 over the original brief: `legacyCandidates[]` (cookie + `~/.ibai/data`) instead of a single `legacyCandidate`; accept = plain `POST /api/data-dir { path }` (no `/legacy/accept` endpoint); `dryRun` on POST; cookie expired only on switch/dismiss — ADR is binding.
2026-09-25  feature/data-page  — Cookie candidate captured in memory only after the Host/Origin prechecks, and offered only while not pinned and no config.json exists — rejected capturing on any request / offering after a choice — a rebinding or cross-site request cannot plant one, and a user who already chose is not nagged.
2026-09-25  feature/data-page  — Candidate expiry keyed off a per-response `settlesLegacy` WeakSet mark — rejected re-parsing the body in the handler wrapper to spot dry runs — the route that switched knows; dry runs and failures never expire the cookie.
2026-09-25  feature/data-page  — `noteCount` = regular `notes/*.md` opening with a `---` fence — rejected full parse via the storage adapter — the adapter reads by catalog id; an 8-byte head check is cheap and matches "parseable" for format v1.
2026-09-25  feature/data-page  — `formatVersion` reported as a constant 1 — rejected reading `manifest.json` now — manifests are ADR 0009 D4 / PR C; absent manifest ⇒ v1 per the ADR.
2026-09-25  feature/data-page  — Banner lives in the App shell above Home/Analytics and fetches `/api/data-dir` itself, failing closed — rejected threading it through Home/Analytics fetch chains — no change to their load states or existing tests; not dismissible at 0 notes (ADR), sessionStorage dismiss only for the restore variant.
2026-09-25  feature/data-page  — Dismiss is per server process (in-memory) — rejected persisting it to disk — no new state file; the cookie is expired on dismiss, and `~/.ibai/data` may reappear after a restart until a folder is chosen.
2026-09-25  feature/data-page-hardening (review #62)  — A note counts only as `notes/<id>.md` whose frontmatter `id:` equals `<id>` and is a catalog id; one rule for noteCount, candidates and the dry-run hint — rejected "starts with `---`" — Obsidian/Jekyll vaults were counted and offered as candidates.
2026-09-25  feature/data-page-hardening (review #62)  — Cookie candidates: up to 3 distinct valid values, newest first — rejected latest-wins — the browser holds one cookie value any localhost page can overwrite, so latest-wins lets a planted value silently replace the real one; a small bounded set shows both and the user picks.
2026-09-25  feature/data-page-hardening (review #62)  — Did NOT persist `~/.ibai/data` dismissals in config.json — rejected `dismissedLegacy` there — recovery is only offered while config.json is ABSENT, and a config.json without `dataDir` is "invalid" to the boot reader (warn + default); making that work means changing the ADR 0005 w2d config contract, not cheap.
2026-09-25  feature/data-page-hardening (review #62)  — Found-folder copy is neutral ("A folder with InterviewBudAI notes was found …"), with the cookie origin labelled "any local page can set it" — rejected "your previous notes" — the candidate can be attacker-suggested.
2026-09-26  feature/w2a-guidance-card  — Guidance chips lead with done/total and the review count, band label second — rejected band-first chips — with little quiz data nearly every band is `unknown` ("Not enough data"), so a band-first chip says nothing; colors/labels still come straight from `STRENGTH_COLORS`/`STRENGTH_LABELS` so Home and Analytics agree.
2026-09-26  feature/w2a-guidance-card  — Back-from-Notes refetch relies on Home remounting on `popstate` (App renders one route at a time) — rejected an extra `popstate` listener in Home — Home is unmounted while Notes shows, so a listener would never fire; the remount already refetches and a test pins it.
2026-09-27  feature/w2c-settings  — Keys stay env-only: the settings page has no input and `/api/settings` returns presence booleans only (`keyConfigured`, `envHelp[].set`) — rejected an in-UI key field — founder decision D5.2 (on-disk keys) is pending; tests assert the key string is absent from every serialized response.
2026-09-27  feature/w2c-settings  — Health check lives in web (`src/settings.ts`), reusing `AnthropicProvider` with a wrapped fetch (timeout + status capture) and a direct `GET /api/tags` for Ollama — rejected a new `healthCheck()` on the provider interface — no interface change/ADR needed; the Anthropic check goes through the exact endpoint/headers the quiz uses.
2026-09-27  feature/w2c-settings  — Test errors are mapped to fixed text by HTTP status (+ an `error.type` only if it matches `^[a-z_]{1,40}$`) — rejected echoing the provider message — `postJson` errors carry the URL and a body snippet, which can hold userinfo or reflected headers.
2026-09-27  feature/w2c-settings  — Ollama endpoint is reported as its origin (scheme://host:port) — rejected host:port without scheme — http vs https matters to the user and the origin can never carry userinfo/path/query.
2026-09-27  feature/w2c-settings  — Rate limit: one test per 5 s per process plus an in-flight guard; `none` answers 400 before the limiter — rejected per-client limits — single local user; the guard also stops overlapping billable calls.
2026-09-27  feature/w2b-custom-problems-ui  — One in-repo accessible `Modal` (dialog/alertdialog, focus to the first field, Tab trap, Escape, focus returns to the opener) for the add/edit form and the delete confirms — rejected a dialog dependency or `<dialog>` — no new deps; jsdom's `<dialog>` support is partial, and one tested component serves all three uses.
2026-09-27  feature/w2b-custom-problems-ui  — After a create, Home refetches the catalog, expands the problem's topics and shows a notice with an "Open its notes" link — rejected auto-navigating to Notes — the brief asks for the row to appear with its badge; the link keeps Notes one click away.
2026-09-27  feature/w2b-custom-problems-ui  — The per-topic "+" is a sibling button of the accordion toggle (existing tests now anchor header queries with `^Label`) — rejected a "+" inside the toggle — nested interactive elements are invalid HTML and unreachable by keyboard.
2026-09-27  feature/w2b-custom-problems-ui  — Delete-then-Home notice travels in an in-memory flash (`lib/flash.ts`: peek in a `useState` initializer, clear in an effect) — rejected a query param or sessionStorage — no URL pollution/refresh replay; peek+clear is StrictMode-safe.
2026-09-27  feature/w2b-custom-problems-ui  — Edit topics are derived from which catalog groups list the problem — rejected adding `topics` to `ApiCatalogProblem` — no API change; `/api/catalog` already groups by every topic a problem has.
2026-09-27  feature/w2b-custom-problems-ui  — CSV "Add as custom problem" picks ONE topic per row (required) + a difficulty (default Medium); topics come from a lazy `/api/catalog` fetch, and ticking is disabled if it fails — rejected a multi-topic picker per row — the brief asks for "topic chosen in the row"; the problem can be edited to 3 topics later.
2026-09-30  feature/small-model-quiz  — "The model isn't ready yet" is its own `role=status` card (amber, Retry) rather than the red error alert; Retry re-runs the normal submit with the kept draft + problemId, so a changed card still gets the 409 path — rejected auto-retry/polling — no background model calls; the user decides when to try again. `ApiError.extra` carries `code/detail/hint` (additive, default `{}`).
2026-09-30  feature/analytics-v2-ui  — Analytics reads only `GET /api/insights` (one call) and `normalizeInsights` degrades a partial/unknown payload to a zeroed `locked` view, emptying focus/slips/strengths unless `unlocked` — rejected trusting the wire blindly — the server lands in parallel (PR 1); a shape drift shows the calm locked page, not a crash.
2026-09-30  feature/analytics-v2-ui  — Donut shares are over the sum of the four buckets (not `status.total`), drawn as stroke-dash arcs on `<circle>`s — rejected `<path>` arcs — dash arcs are trivially testable (lengths sum to 1, zero-total → all 0) and need no trig; no chart library.
2026-09-30  feature/analytics-v2-ui  — Miss labels: API label first, then a client `MISS_LABELS` map, then "Other slip" — rejected showing an unknown raw code — a future code reads as plain words, never an internal id.
2026-09-30  feature/analytics-v2-ui  — Each unlocked section shows "Not enough quiz data yet in this section." when empty, and Strengths drops any Focus topic client-side too — rejected hiding empty sections — `state` comes from the session count only, so an unlocked page can have empty sections; a stable layout is calmer.
2026-09-30  feature/analytics-v2-ui  — Removed `StatusBreakdownChart`, `TopicCompletionChart`, `CompetencyChart` and their helpers; `competency.ts` keeps only `STRENGTH_COLORS`/`STRENGTH_LABELS` (Home's guidance card uses them); `fetchCompetency` stays as the endpoint stays — rejected keeping the old helpers — no remaining callers.
