# Decision Log

- **m5-chat**: ADR 0006 M5 — moved the interview coach chat into the SPA at `/app/interview` and added the JSON chat-turn endpoint it needs. Scope `packages/web` (server endpoint) + `packages/web/web-ui` (React page); core/storage/providers/curriculum interfaces UNCHANGED (the provider is consumed via the existing DI, not re-shaped). **Server**: new `POST /api/chat` in the `/api` handler (`api.ts`). Chose the canonical `{ messages: [{role:'user'|'assistant', content}, …] }` shape (prior transcript + the new user turn) over `{transcript, message}` — one shape, matches the OpenAI/Anthropic mental model and the SPA's optimistic-append state (the transcript already ends with the user's turn), and documented it in the README + endpoint table. The body is untrusted → validated by `parseChatMessages`: must be a non-empty array of well-formed turns (role ∈ {user,assistant}, non-empty string content, trimmed) **ending in a `user` turn**, else `400`; a `system` role in the body is rejected (only the server injects the system persona, so a client can't override it). It builds `PromptMessage[] = [{role:'system', content: INTERVIEW_COACH_PERSONA}, …conversation]` — the persona is the **same text** as the server-rendered `POST /coach` persona, elicits the candidate's reasoning and ships NO canned solutions (§6.2) — calls `provider.complete()`, and returns `{ reply }` (the model's trimmed text; empty output → `502`, never fabricated). Provider **REQUIRED**: none → `400 {error:'no model configured', detail}` (mirrors coach). On provider reject, reused the same `isConnectionError`/`isAuthError` classifiers (copied into `api.ts` to keep the module self-contained, matching how `api.ts` already holds its own helpers) → `502` with a message distinguishing connection vs auth vs malformed; wrong method → `405`; never crashes. Wired the provider through: added `provider?: LlmProvider` to `ApiDeps` and `handler.ts` now passes `deps.provider` into `handleApiRoute` (the only server change outside `api.ts`). **React**: `Interview.tsx` renders a transcript (you=emerald right / coach=slate left; JSX auto-escaped + `whitespace-pre-wrap`; **no `dangerouslySetInnerHTML`**) + a composer (Enter sends, Shift+Enter newline). Send optimistically appends the user turn, `POST`s the whole transcript via new `postChat`, and appends the model `{reply}`; a "thinking" spinner shows while awaiting. Provider-required "Configure a model to start (ANTHROPIC_API_KEY + IBAI_ANTHROPIC_MODEL or IBAI_OLLAMA_MODEL)" state is gated up-front via `GET /api/config` (provider label ≠ "No model configured") and defensively again if a send returns `400`. A failed send shows a friendly **inline banner and preserves the transcript** (surfacing the server's JSON `error`) — never loses the chat, never crashes. `postChat` throws an `ApiError` carrying the server's `error` string + status so the page can special-case the `400`. Reused the existing History-API router: added an `interview` route to `parseRoute` + `interviewHref()` (no routing lib); reworked the **Interview** nav link in `App.tsx` from the server-rendered `/coach` to the SPA route (client-side `navigate` + active state); the old `/coach` stays until M6. `scrollIntoView` is feature-guarded (jsdom lacks it). No new deps. Tests: server `api.test.ts` uses a fake **counting** `LlmProvider` (no network) — 200 `{reply}` asserting persona+order and exactly one call, multi-turn order, `400` no-provider (provider never called), `502` connection/auth/empty-output, `400` malformed JSON / non-array / bad-role / not-ending-in-user, `405` GET; React `Interview.test.tsx` (mocked fetch) — renders composer, Send appends user turn + posts transcript + appends reply + clears composer, multi-turn transcript forwarded, no-provider state (no chat call), send error → inline banner preserving the transcript, `400` → configure state, XSS payload rendered as literal text (no injected `<img>`), plus `App.test.tsx` (Interview link → `/app/interview`, client-side nav sets `aria-current`, direct load) and `router.test.ts` interview parse/href. Verified from CLEAN `npm ci` → `npm run verify` GREEN: typecheck(.tsx) + `eslint .` + `prettier --check .` + `tsc --build` + `build:ui` + tests (node 25 files/441 tests + web-ui 11 files/70 tests); standalone `build:ui` succeeds; built `dist-ui/index.html` references only local `/app/assets/*` (no external CDN — the sole `https://` in the JS is React's bundled error-decoder URL string, not a network/asset ref). PR open on `feature/m5-chat`.

- **m1-json-api**: ADR 0006 M1 — added the same-origin, localhost-only JSON API under `/api` that the React SPA (M2+) will consume. `packages/web` only; core/storage/providers/curriculum interfaces UNCHANGED; no new deps. New `src/api.ts` (pure response builders + `isApiRoute`/`handleApiRoute`) intercepted early in `handler.ts` (right after the `/app` block) so existing server-rendered routes and `/app` are untouched. Endpoints: `GET /api/catalog` (catalog grouped by topic alphabetically — mirrors the server-rendered table — each problem `{id,title,url,difficulty,status,completed}` + `totals:{total,byStatus}`), `GET/POST /api/notes/:id` (id validated against catalog → 404 unknown; POST body untrusted → validated, malformed/invalid-status → 400; keeps `completed` ⇔ `status:'done'` via the storage rule; preserves existing content/attempts on partial update), `GET /api/progress` (`{completed,total,byStatus}` reusing `computeStatusCounts`), `GET /api/config` (`{dbConfigured,dataDir?,provider}`, dataDir display-only + omitted when no DB). Data dir resolved per-request via the same `resolveDataDirWithCookie` cookie>env>default precedence; no-DB is a first-class safe state (catalog/progress all-none; notes GET `{dbConfigured:false}`; notes POST `400 {error:'no database configured'}` — never crashes). Chose a separate `api.ts` module (not inlining into `handler.ts`) to keep the router pure/testable and the diff isolated.
