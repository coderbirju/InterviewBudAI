# Decision Log

- **m3-notes**: ADR 0006 M3 — built the React Notes/intuition editor in the SPA at `/app/notes/<id>`, replacing the server-rendered `/notes/<id>` for SPA users (the old HTML route stays until M6). Scope was `packages/web/web-ui` only; the M1 API and core/storage/providers/curriculum interfaces are UNCHANGED (consumed as-is); no new deps and no server wiring needed — `spa.ts` already SPA-falls-back extensionless deep paths under `/app` to `index.html`, so `/app/notes/:id` loads the bundle. New `src/components/Notes.tsx` fetches `GET /api/notes/:id` and pre-fills every field: title (from `GET /api/catalog`, links to the LeetCode url `target=_blank rel=noopener`; **falls back to the problem id** as a plain heading if the catalog fetch fails, since the id is already validated), the 4-state Status control (reused M2 `StatusControl`), a free-text intuition `textarea`, and Time/Space complexity inputs. Save `POST`s `{content,status,timeComplexity,spaceComplexity}` via new `saveNote`, then shows a **"Saved"** confirmation and reconciles local state with the server response; any field edit clears a stale confirmation. Modeled `GET /api/notes/:id` as a discriminated `NoteFetchResult` (`{dbConfigured:false}` | `FullNote`) so states map cleanly: no-DB → create-database CTA (→ `/setup`); a `404` `ApiError` → friendly "Problem not found"; other fetch failures → inline load error; a save failure → inline save error (400 → "no database configured", else generic) — none crash. Chose to add a **tiny in-repo router** (`src/lib/router.ts`: `parseRoute`/`navigate`/`useRoute` on the History API + React built-ins) instead of a routing library — M2 had no router and the ADR/charter keep deps minimal; `App.tsx` now switches Home vs Notes on the path, and Home's `ProblemRow` Notes link points at `/app/notes/<id>` with `pushState` client-side nav (plain-link fallback for modified/middle clicks). All values render via JSX (auto-escaped); no `dangerouslySetInnerHTML`. Reused the M0/M2 Tailwind tokens (slate/emerald, `status.*` colors) and `transition-all duration-200`; back-to-Home link on every state. Tests: `Notes.test.tsx` (8) — render+prefill from mocked `fetchNote`+`fetchCatalog`, title-fallback on catalog failure, Save POSTs the exact fields + shows "Saved", status selector sets a different one of the 4 states then saves it, no-db CTA, `404` not-found, network load error, save-failure inline error; `router.test.ts` (parse/href/encoding). Verified from CLEAN `npm ci` → `npm run verify` GREEN: typecheck + `eslint .` + `prettier --check .` + `tsc --build` + `build:ui` + tests (web-ui 7 files/32 tests; node suite unchanged). `build:ui` succeeds. PR open on `feature/m3-notes`.

- **m1-json-api**: ADR 0006 M1 — added the same-origin, localhost-only JSON API under `/api` that the React SPA (M2+) will consume. `packages/web` only; core/storage/providers/curriculum interfaces UNCHANGED; no new deps. New `src/api.ts` (pure response builders + `isApiRoute`/`handleApiRoute`) intercepted early in `handler.ts` (right after the `/app` block) so existing server-rendered routes and `/app` are untouched. Endpoints: `GET /api/catalog` (catalog grouped by topic alphabetically — mirrors the server-rendered table — each problem `{id,title,url,difficulty,status,completed}` + `totals:{total,byStatus}`), `GET/POST /api/notes/:id` (id validated against catalog → 404 unknown; POST body untrusted → validated, malformed/invalid-status → 400; keeps `completed` ⇔ `status:'done'` via the storage rule; preserves existing content/attempts on partial update), `GET /api/progress` (`{completed,total,byStatus}` reusing `computeStatusCounts`), `GET /api/config` (`{dbConfigured,dataDir?,provider}`, dataDir display-only + omitted when no DB). All JSON: unknown `/api` → 404 JSON, wrong method → 405 JSON, never HTML. Data dir resolved per-request via the same `resolveDataDirWithCookie` cookie>env>default precedence; no-DB is a first-class safe state (catalog/progress all-none; notes GET `{dbConfigured:false}`; notes POST `400 {error:'no database configured'}` — never crashes). Chose a separate `api.ts` module (not inlining into `handler.ts`) to keep the router pure/testable and the diff isolated. Verified from CLEAN `npm ci` → `npm run verify` GREEN (25 files / 430 tests incl. typecheck+lint+prettier --check+build) and live curl on a running server: POST done/to_revisit persist to disk (frontmatter) and round-trip via GET; catalog embeds per-problem status; progress counts reflect the seed (done=1,to_revisit=1,total=175); config dbConfigured true/false; 404/400/405 all JSON; `/` and `/app` still 200; no-DB state confirmed live.
